# 推测睡眠算法说明

实现位置：`algorithm` 模块，入口为 `SleepCalculator.compute(...)`。该模块不依赖 Android 框架。

时区固定为 `Asia/Shanghai`。`day_date` 是**夜间窗口开始的那个日历日**（当天 22:00 所属的日期），即使醒来已经是次日。

## 步骤

1. **排序事件**：按时间戳升序；同一毫秒时先处理 `PAUSED`，再处理 `RESUMED`，便于处理应用切换。
2. **组装前台会话**
   - `RESUMED` 开始一段会话；同一包连续多次 `RESUMED`（Activity 内跳转）保留第一次开始时间。
   - `PAUSED` 关闭对应包的会话。
   - **未匹配的 PAUSED**（没有对应的打开会话）直接忽略。
   - **应用切换**：若 A 仍打开时出现 B 的 `RESUMED`（部分 ROM 可能丢 PAUSED），在 B 的开始时刻关闭 A，避免会话重叠。
   - **区间结束仍未关闭的 RESUMED**：把结束时间填为 `rangeEnd`，仅供会话预览，并标记 `closed = false`。这个填充时间**不能**当作「上一次使用结束」去作为入睡点。
3. **计算静默间隙**：会话按开始时间排序后，间隙 = 上一段已关闭会话的结束时间 → 下一段会话的开始时间。
   - 不从 `rangeStart` 凭空造一条「采集开始前」的间隙。
   - 若没有下一次使用，开口间隙不视为睡眠——醒来必须是真实的下次使用开始时间。
4. **过滤**
   - 间隙时长 ≥ `MIN_SLEEP_GAP_MS`（默认 90 分钟）；
   - 且与至少一个夜间窗口有正时长重叠。夜间窗口为当天 22:00 至次日 10:00（半开区间重叠判断：`gapStart < windowEnd && gapEnd > windowStart`）。
   - 入睡 / 醒来时间使用真实的会话边界，**不会裁剪到 22:00 或 10:00**。因此 20:00 放下手机、次日 07:00 再打开，入睡时间记 20:00。
5. **窗口归属**：一条长间隙若与两个夜间窗口都重叠，归给**重叠更长**的那个窗口；重叠时长相同则取更早的日期。同一间隙绝不会记成两天的睡眠。
6. **每日取值**：每个夜间窗口只保留最长的一条合格间隙作为当日推测睡眠。
7. **raw_sessions**：与该夜间窗口相交的前台会话，并至少包含入睡前最后一次会话，供界面预览。

## 日志

App 层会把每条间隙的起止、时长、是否通过过滤、过滤原因、是否被选为当日睡眠打印到 `SleepCollect`。
